# 横屏游戏页：槽位与快照

状态：0.9.0 已实现。本文记录 2026-11-17 确认的横屏游戏页与槽位/快照交互，设计参考稿用于讨论；当前操作和迁移说明见 [使用说明](usage.md#存档与读档)。

## 界面目标

- 用途：合并游戏详情、开局进度选择、暂停管理及快照操作，仅设计横屏。
- 记忆点：每款游戏有 3 条持续推进的进度，历史快照单独保留。
- 样式：沿用 Islands 的炭灰表面、电光蓝强调色、16sp 正文、20sp 焦点标题、16dp 外边距、48dp 最小按钮高度和主题统一圆角。
- 交互：开局选定槽位，本局不得切换；快照应用必须明确目标与覆盖结果；确认框默认取消。
- 参考：沿用项目现有游戏页的左右分区和独立圆角表面，不增加假封面、ROM 画面或竖屏稿。

可点击稿：[game-page-slots-snapshots.html](design/game-page-slots-snapshots.html)。预览的“开局前 / 暂停中”为演示控件，不属于 APP 页面；存档时间和进度标识仅为示例。

## 横屏布局

- 顶部：返回、游戏名称、收藏。暂停状态明确标识当前槽位。
- 左侧：封面（无图时显示游戏名）、主操作、当前/待选槽位提示、游戏信息。
- 右侧：“槽位 / 快照”两项局部标签，切换同一页的内容，避免横屏高度不足时堆两排截图。
- 槽位标签：3 张等宽槽位卡片，始终显示 1、2、3，包括空槽位。下方说明选中槽位的行为，提供删除进度。
- 快照标签：按生成时间倒序分页展示快照；每页 3 张，提供截图、时间、来源槽位、应用和删除。暂停时提供“生成快照”。数量不设产品上限，列表分批读取，不要求一次解码所有截图。
- 横屏高度不足时，先缩小/收起封面及次要信息，再允许内容区滚动；主操作、当前槽位和关键按钮保持可达。不通过缩小字号来塞内容。
- 折叠时避开真实铰链；保留当前标签、槽位、快照页码、焦点和游戏会话。只适配横屏范围内的窗口变化。

## 数据和状态

| 对象 | 规则 |
| --- | --- |
| 槽位 | 每款游戏固定 3 个，删除的是进度，不删除槽位本身 |
| 空槽位 | 没有进度，从头开始；不是额外的系统自动槽位 |
| 开局选择 | 页面选中某个槽位，按“开始游戏”才把它绑定为本局槽位 |
| 本局槽位 | 成功开局后固定到本局结束，暂停中不允许切换 |
| 自动保存 | 退出与切后台等自动保存均更新本局槽位，不单独生成第四个系统自动档 |
| 快照 | 手动生成的独立历史进度，记录时间、来源槽位、核心版本及可选截图；之后不跟随槽位更新 |
| 应用快照 | 复制快照到目标槽位，快照本身不修改、不消耗；不会新增或切换本局槽位 |

浏览焦点、开局前选中槽位、本局槽位是不同状态。标签切换、快照翻页及浏览卡片都不得改变本局槽位。

## 开局前

1. 默认选中上次成功使用的槽位，首次为槽位 1。初始焦点放在“开始游戏”。
2. 左侧注明“将从槽位 N 继续”或“槽位 N 为空，将从头开始”。方向键进入右侧选择槽位，A 确认选择，不直接启动游戏。
3. 选择空槽位后开始游戏即从头开始；不新增槽位。
4. 选中已有进度可执行“删除进度”。确认框写明目标槽位与不可恢复后果；删除后卡片变空，仍保持相同编号和选择。
5. 应用快照：选快照 → “应用到槽位” → 选 1/2/3 → 最终确认。覆盖已有进度和写入空槽位都明确确认目标；确认默认聚焦取消。
6. 应用成功后选中目标槽位、回到槽位标签并聚焦开始游戏，不自动启动。

## 暂停中

1. 默认聚焦“恢复”。始终显示“本局：槽位 N”，其他槽位不可选择；“切换槽位”不作为操作出现。
2. “生成快照”捕获当前运行进度，成功后新增一个快照。生成快照不改变当前槽位，也不隐式覆盖槽位文件。
3. 应用快照的目标固定为本局槽位。预览框显示源快照与“槽位 N（本局）”，不提供切到其他槽位的入口。
4. 最终确认文案示例：“将用快照覆盖槽位 1 的已保存进度，并替换当前运行进度。当前未保存的进度会丢失，快照仍会保留。”按钮为“取消 / 应用到槽位 1”。
5. 成功时槽位文件、当前模拟器进度和预览状态同步更新，游戏保持暂停，聚焦恢复。之后的自动保存基于应用后的进度，不得将应用前的旧运行进度写回。
6. 不提供独立“重新开始”按钮。需要重开时删除本局槽位进度，确认文案为：“删除槽位 N 的进度并结束本局？本局不会再次自动保存。已有快照不受影响。”按钮为“取消 / 删除并结束本局”。
7. 删除本局槽位的顺序必须避免退出/销毁/后台回调重新写档：先阻止本局后续自动保存并结束会话，安全删除后回到同一游戏的开局页，选中该空槽位。失败不显示删除成功；无法继续会话时保留原存档并提供返回与重试。
8. 正常“退出”先保存本局槽位，再回来源列表。失败留在暂停页提示重试，不把失败显示成已保存。

## 快照管理和失败处理

- 快照默认按时间倒序；生成成功后显示最新快照，删除后选中相邻项，空页回上一页，快照为空时保留槽位和主操作。
- 删除快照仅删除该历史副本，不修改槽位，也不影响已经从它恢复的游戏；仍需确认。
- 应用前验证快照可读性、游戏标识和核心版本，必要的版本风险确认先于写入。取消操作不修改任何数据。
- 暂停应用快照是一次完整操作：先暂存原运行状态与槽位，再验证并加载目标进度，持久化成功后才发布成功。期间禁用恢复、退出、删除、重复应用，并阻止生命周期自动保存与它竞争。
- 加载或写入失败时恢复原槽位与原运行状态；若运行状态无法恢复，保持停止/错误状态并禁止自动保存，原槽位与快照文件仍保留。
- 写入沿用临时文件、落盘和原子替换，截图和进度必须对应。截图缺失可以占位，但不能宣称生成失败的快照已经存在。
- 空间不足时保留原文件并提示清理快照，不自动清理历史快照。没有产品数量上限不等于忽略实际存储容量。
- 升级时旧自动档迁入槽位 1，旧自动档和全部手动档都迁入独立快照，原文件仍保留。迁移完成标记防止删除新槽位后又被旧档重新填回；损坏的旧包同样保留，不静默丢弃。

## 手柄和返回

- 方向键/左摇杆移动焦点，A/Enter 确认，B/系统返回关闭最上层。关键操作都有可见按钮。
- 开局前返回来源卡片；暂停时返回恢复游戏；确认框取消返回发起操作。标签页不是额外的返回层。
- L1/R1 可在快照标签翻页，页面同时提供上一页/下一页按钮；保留格位，缺项时选同页相邻项。
- 选中项用勾选与文字表达，焦点使用现有 2dp 蓝色描边，实心蓝按钮用亮边；两者不混淆。
- 当前槽位和被选快照均使用稳定标识，窗口变化、生成、删除和应用后按稳定标识恢复焦点。

## 横屏锁定与验收

应用现有 `AndroidManifest.xml` 已将 `MainActivity` 设置为 `screenOrientation="landscape"`，并通过应用级 `android.window.PROPERTY_COMPAT_ALLOW_RESTRICTED_RESIZABILITY=true` 申请在 Android 16 大屏保留方向限制。此方向约束从启动覆盖所有页面；不通过在各页面反复修改 `requestedOrientation` 实现。

横屏锁定不等于忽略折叠、窗口大小和系统安全区；保留已有 `configChanges` 与单份 `GLRetroView`。系统多窗口、厂商强制方向等行为需要在实际设备验证，不把仅检查配置当成真机验证。

验收时覆盖：设备竖直握持冷启动、打开系统自动旋转后转动设备、详情/设置/暂停/确认框、折叠和展开；正常全屏均应保持横屏，不出现竖屏产品布局。还要验证暂停应用快照后退出/切后台不会恢复旧进度，以及删除本局槽位后不会被生命周期自动保存重新生成。
