# 使用说明

## 配置游戏库目录

在「设置 → 导入」里选「添加文件夹」，可以添加多个本地目录。添加后和每次启动应用时，应用会递归扫描这些目录里的 ZIP。目录有变动时也可以选「重新扫描」。扫描结果会显示已识别的游戏、BIOS 和跳过的 ZIP 数量。移除目录会保留原文件和存档。

扫描时读取 ZIP 的文件索引来识别套件。再次扫描时，应用会复用大小和修改时间都未变的文件结果。已有游戏库在后台扫描期间可用，新识别的游戏会陆续加入列表。开始游戏时，应用会完整校验该游戏和它所需的父套件及 BIOS。

新增游戏时请把 ZIP 放到所配置的目录。多个版本共用相同 ROM 内容时，请用对应的 FBNeo 套件名命名 ZIP。旧版已导入的 ZIP 仍可使用，也可按已记录的原始文件名搜索。

游戏库会显示已识别的游戏。克隆版缺少父套件或 BIOS 时，详情会列出缺少的 ZIP。游戏、父套件和 BIOS 可以来自不同目录，也可以与旧版已导入的 ZIP 搭配。如果游戏 ZIP 已经包含所需的父套件和 BIOS 文件，就可以直接启动。目录里的 ZIP 只在启动相关游戏时复制到临时目录。

## 游戏封面

收藏、最近卡片和游戏详情支持真实封面。联网时，应用在后台为收藏或成功玩过的游戏获取缺失封面，不扫描下载整个游戏库。断网时任务等待联网，关闭界面后也由系统安排继续，系统省电限制可能延后执行。已有封面保存在应用私有目录，离线可用，下载失败时保留旧图，没有图片时显示游戏名。

「设置 → 游戏封面」提供「获取缺失封面」和「更新封面」，两者仍只处理收藏或玩过的游戏，后者会重新下载已有图片。手动任务显示等待、结果和失败数量。游玩范围复用「最近」中的成功启动记录，已有记录在升级后也可获取封面。取消收藏后，已玩过的游戏仍会参与获取，已有图片不会被删除。

图源使用 `Named_Boxarts` 目录的真实封面。内置索引按固定 DAT 的英文描述匹配，缺图时沿 `cloneof` 查找父游戏的封面。手动更新会从同一路径获取最新图片。APK 只包含路径索引。本地自定义封面目前还未实现。[Libretro FBNeo 图库](https://github.com/libretro-thumbnails/FBNeo_-_Arcade_Games)

图库新增或重命名图片后，可在仓库根目录运行 `python3 tools/update_cover_index.py` 更新内置索引，也可用 `--tree` 指定已保存的完整 GitHub tree 响应。[封面索引脚本](../tools/update_cover_index.py)

## 浏览与筛选

启动后进入「收藏」，收藏和最近使用等尺寸的横滑封面卡片，卡片撑满标题下方的可用高度，宽度随封面区高度调整。图片裁切填满封面区，无封面时在同一位置显示游戏名。可从收藏卡片开始游戏，也可在游戏库的详情中添加或取消收藏。宽窗口用左侧栏，窄窗口用底部栏，导航依次为「收藏」「最近」「游戏库」「设置」。「最近」按实际启动游戏的顺序排列，同一款游戏只显示一次，重开应用后仍会保留。

游戏库每页固定 2 列 × 5 行，共 10 个游戏，按列从上到下排列。卡片平分可用宽高，末页保留相同尺寸。游戏名和来源文件名都为单行，超长省略。卡片较矮时两者并排显示。游戏库的字母筛选、状态筛选和分页与标题同一行。可用「上一页」「下一页」或手柄 L1 / R1 翻页，打开详情再返回时回到原游戏所在页。

字母筛选面板按窗口宽高排键，所有按键同时可见。可以连续输入字母、数字、点、下划线和连字符，支持退格、清空和完成，无结果时仍可继续编辑。筛选匹配中文名拼音首字母、英文描述、套件文件名和实际来源 ZIP 文件名，忽略大小写，例如 SGZJ 匹配三国战纪，HJDT 匹配合金弹头，KOF98 或 kof98.zip 匹配拳皇对应文件。修改筛选条件后回到第一页。

「导入」和「同步」从设置进入，页头显示「设置/导入」或「设置/同步」。同步页显示「即将推出」。设置也显示核心版本和手柄映射说明。

在「设置 → 圆角大小」可单选「更小」（8dp）、「默认」（12dp）或「更大」（16dp）。选择后全局即时生效，重开应用后仍会保留。用手柄时，左右方向键移动焦点，A 确认。

## 暂停与重置

系统侧滑返回和返回键都会先暂停画面与声音并打开暂停页。再返回一次会自动存档并退出游戏。存读档弹窗和确认框打开时，返回先关闭当前面板。暂停页默认聚焦「恢复」，下方是「存档 / 读档」和「重置 / 退出」两组操作。手柄菜单功能键（Android MENU / BUTTON_MODE，实体键取决于设备映射）可打开或关闭暂停页，B 恢复游戏。切回前台仍保留暂停页和暂停状态。确认重置后，应用清除当前游戏的自动存档和全部手动槽位，再从头启动当前游戏。

## 存档与读档

每款游戏有 1 个自动存档和最多 10 个手动槽位。进入游戏会读取自动存档，退出按钮、暂停页再次系统返回和切到后台会更新自动存档。打开「存档」或「读档」会暂停画面和声音，并显示槽位弹窗。自动存档固定在左侧，只允许读取。手动槽位在右侧横向滚动，可用触屏滑动或手柄方向键选择。「新建槽位」是手动槽位列表最后一张卡片，与其他手动槽位一起横向滚动，可连续新建，自动存档仍固定在左侧。达到 10 个手动槽位上限后，末尾的新建卡片显示「已达上限」并禁用，只能覆盖已有槽位。覆盖已有槽位需要确认，读取任何槽位前都会提示当前未存档进度将丢失。关闭弹窗会恢复打开前的暂停状态，确认提示取消后仍留在槽位弹窗中。

新存档写在 `files/states/<套件名>/slot<N>.save`，其中 `slot0.save` 是自动存档，`slot1.save` 起是手动槽位。每个文件包含进度、核心提交号、保存时间，有截图时也会附上。打开暂停页前会尝试截取一张游戏画面，存档时复用，恢复游戏时丢弃。截图失败时仍可存档，槽位会显示占位提示。先写临时文件、`fsync` 落盘，再原子替换槽位，防止进度和封面对不上。原有 `slot0.state` / `slot0.properties`（包括 `kovsh` 的旧存档）仍可作为自动存档读取。读档失败会保留原文件并停止自动覆盖，避免破坏旧进度，可重新读档或重置游戏。核心提交号不一致时会提示，因为 FBNeo 不保证跨版本读档。

## 手柄与画面

有线和蓝牙手柄走 LibretroDroid 现成的按键和摇杆转发（包含 Android 和 RetroPad 的 A/B、X/Y 对调，以及 `controllerNumber` 分端口）。这一阶段没有映射界面。

应用从启动起固定为横屏，大屏同样申请保留横屏限制。游戏画面铺满安全区内的播放区域，由 LibretroDroid 按核心报告的宽高比居中：比屏幕窄就左右留黑边，比屏幕矮就上下留黑边。比例来自核心的 AV info，运行中如果核心用 `SET_GEOMETRY` 改了比例，黑边会跟着重算。读不到比例时才退回 4:3，画面仍然不缩小。

黑边保持纯黑，无论宽窄都不放常驻按钮，也不叠加悬浮控件，操作集中在暂停页，因此不依赖加载前预测黑边尺寸，不为控件缩小游戏画面。暂停页使用不透明背景，只在暂停或出错时显示。`MainActivity` 自己处理 `configChanges`，游戏画面是同一个 `GLRetroView`，只改它的尺寸，不新建核心。旋转、折叠、窗口大小、系统栏和挖孔都会重算。系统如果仍然重建 Activity（比如没列进 `configChanges` 的变化），这次游戏会结束，进度靠自动存档恢复。`GLSurfaceView` 不能跨进程保留，进程死亡后会在下次启动游戏时自动读档。

游戏库在窗口宽度达到 600dp，或处于书本姿态的竖直铰链时，用左侧导航栏，更窄的窗口用底部导航栏。壳层外边距统一 16dp，左侧栏缩为 96dp，为分页目录留出更多空间。
