# 使用说明

## 配置游戏库目录

在「设置 → 导入」里选「添加文件夹」，可以添加多个本地目录。添加后和每次启动应用时，应用会递归扫描这些目录里的 ZIP。目录有变动时也可以选「重新扫描」。扫描结果会显示已识别的游戏、BIOS 和跳过的 ZIP 数量。移除目录会保留原文件和存档。

扫描时读取 ZIP 的文件索引来识别套件。再次扫描时，应用会复用大小和修改时间都未变的文件结果。已有游戏库在后台扫描期间可用，新识别的游戏会陆续加入列表。开始游戏时，应用会完整校验该游戏和它所需的父套件及 BIOS。

新增游戏时请把 ZIP 放到所配置的目录。多个版本共用相同 ROM 内容时，请用对应的 FBNeo 套件名命名 ZIP。旧版已导入的 ZIP 仍可使用，也可按已记录的原始文件名搜索。

游戏库会显示已识别的游戏。克隆版缺少父套件或 BIOS 时，详情会列出缺少的 ZIP。游戏、父套件和 BIOS 可以来自不同目录，也可以与旧版已导入的 ZIP 搭配。如果游戏 ZIP 已经包含所需的父套件和 BIOS 文件，就可以直接启动。目录里的 ZIP 只在启动相关游戏时复制到临时目录。

## 游戏封面

收藏、最近卡片和游戏详情支持真实封面。联网时，应用在后台为收藏或成功玩过的游戏获取缺失封面，不扫描下载整个游戏库。断网时任务等待联网，关闭界面后也由系统安排继续，系统省电限制可能延后执行。已有封面保存在应用私有目录，离线可用，下载失败时保留旧图，没有图片时显示游戏名。

「设置 → 游戏封面」提供「获取缺失封面」和「更新封面」，两者仍只处理收藏或玩过的游戏，后者会重新下载已有图片。手动任务显示等待、结果和失败数量。游玩范围复用「最近」中的成功启动记录，已有记录在升级后也可获取封面。取消收藏后，已玩过的游戏仍会参与获取，已有图片不会被删除。

图源使用 `Named_Boxarts` 目录的真实封面。内置索引按固定 DAT 的英文描述匹配，缺图时沿 `cloneof` 查找父游戏的封面。手动更新会从同一路径获取最新图片。APK 只包含路径索引。本地自定义封面目前还未实现。[Libretro FBNeo 图库](https://github.com/libretro-thumbnails/FBNeo_-_Arcade_Games)

图库新增或重命名图片后，可在仓库根目录运行 `python3 tools/update_cover_index.py` 更新内置索引，也可用 `--tree` 指定已保存的完整 GitHub tree 响应。[封面索引脚本](../tools/update_cover_index.py)

## 浏览与筛选

启动后进入「收藏」，收藏和最近每页最多 4 款游戏，等大的封面卡片按内容区宽高排成一行四列或两行两列，铺满标题下方的可用区域。末页卡片保留相同尺寸。标题右侧依次显示「上一页」、页码和「下一页」，每项各占一个岛。也可用手柄 L1 / R1 翻页。翻页后焦点留在同一格，空缺时聚焦新页第一项。图片裁切填满封面区，无封面时在同一位置显示游戏名。选中收藏、最近或游戏库的卡片都会先打开同一个游戏页。可在游戏页开始游戏、读档、添加到收藏或取消收藏。宽窗口的左侧栏由四个等高按钮铺满，窄窗口用底部栏，导航依次为「收藏」「最近」「游戏库」「设置」。「最近」按实际启动游戏的顺序排列，同一款游戏只显示一次，重开应用后仍会保留。

游戏库每页固定 2 列 × 5 行，共 10 个游戏，按列从上到下排列。卡片平分可用宽高，末页保留相同尺寸。游戏名和来源文件名都为单行，超长省略。卡片较矮时两者并排显示。游戏库的字母筛选、状态筛选和分页各自成岛。空间足够时与标题同行，窄窗口里控件排在标题下方。游戏列表一屏显示整页。用 Y 或页头的「字母筛选」打开搜索。「完成」聚焦搜索结果，返回关闭搜索并聚焦页头入口。可用「上一页」「下一页」或手柄 L1 / R1 翻页，焦点保留在同一格，空缺时聚焦第一项。用手柄 A 打开可运行游戏的游戏页，会聚焦「开始游戏」。返回时恢复原卡片焦点。从收藏页打开游戏页并取消收藏后，返回时聚焦相邻卡片。

字母筛选面板按窗口宽高排键，宽窗口下使用更窄的面板和更多排按键，所有按键同时可见。可以连续输入字母、数字、点、下划线和连字符，支持退格、清空和完成。输入时只编辑草稿，点击「完成」后才计算并显示筛选结果，回到第一页并聚焦结果；返回或关闭面板会放弃本次修改，保留原来的筛选和页码。无结果时仍可重新打开面板编辑。筛选匹配中文名拼音首字母、英文描述、套件文件名和实际来源 ZIP 文件名，忽略大小写，例如 SGZJ 匹配三国战纪，HJDT 匹配合金弹头，KOF98 或 kof98.zip 匹配拳皇对应文件。

「导入」和「同步」从设置进入，页头显示「设置/导入」或「设置/同步」。同步页显示「即将推出」。设置还提供核心版本信息。

在「设置 → 圆角大小」可单选「更小」（8dp）、「默认」（12dp）或「更大」（16dp）。选择后全局即时生效，重开应用后仍会保留。用手柄时，左右方向键移动焦点，按菜单确认键提交。

## 暂停与重新开始

游戏中使用系统返回或手柄暂停键会打开同一款游戏的游戏页，并暂停画面和声音。暂停时默认聚焦「恢复」，左侧显示本局绑定的槽位，右侧「槽位 / 快照」切换同页内容。返回或再按暂停键恢复游戏；确认框打开时，返回只取消最上层。主手柄断连同样会暂停，重新连接后自行恢复。

每款游戏固定有 3 个槽位，只能在开局前选择，本局开始后无法切换。「保存并退出」和切到后台会更新本局槽位，不再保留单独的系统自动存档槽位。保存失败会留在暂停页提示重试。

需要从头开始时，在开局前选中槽位并「删除进度」，确认后该槽位变空，再开始即可。暂停时删除本局槽位，会明确确认「删除并结束本局」：结束游戏、阻止后续自动保存，回到同款游戏的开局页，选中刚清空的槽位。固定编号仍保留，历史快照不受影响。不再提供独立的重新开始按钮。

## 存档与读档

槽位负责持续游玩的进度，快照负责保留某个时刻的历史进度。开局前默认选中上次成功使用的槽位，首次为槽位 1；选择槽位不立即启动，按「开始游戏」才恢复其进度。空槽位从头开始。恢复失败会保留文件并禁止自动覆盖，可退出后应用兼容快照，或明确删除该槽位后重新开始。

暂停时从「快照」标签选择「生成快照」，保存当前运行进度。生成快照不改变自动保存目标，也不隐式更新槽位。快照不设产品数量上限，按生成时间倒序分页，每页最多 3 张，可用上一页/下一页按钮或手柄 L1/R1 翻页。快照显示截图、时间及来源槽位，旧版迁入的快照标记为「旧版存档」。截图缺失不影响进度保存。

开局前应用快照时，先选快照，再选目标槽位，最后确认覆盖。成功后选中目标槽位，仍需按「开始游戏」。暂停时应用快照的目标固定为本局槽位，确认后同时覆盖该槽位文件和当前实际运行进度，保持暂停并聚焦「恢复」；之后的自动保存使用应用后的进度。原快照保留，不会被消耗或跟随游玩更新。核心版本不一致时会在确认框说明，FBNeo 不保证跨版本读档。

应用过程中暂停自动保存并禁止恢复、退出、重复应用与删除。读取或写入失败保留原槽位；已开始替换运行状态时会尝试恢复原状态，恢复失败则停止游戏并禁用自动保存，避免写坏原进度。删除快照需确认，只删除历史副本，不影响已经恢复到槽位或正在运行的进度。

新槽位保存在 `files/states/<套件名>/progress/slot1.save` 至 `slot3.save`，快照保存在同级 `snapshots/slot<N>.save`。文件包含进度、核心提交号、时间和可选截图，快照另记来源槽位。写入使用临时文件、落盘和原子替换，避免进度与截图不一致。

从旧版本首次升级时，旧自动档迁入槽位 1，旧自动档和所有手动档都迁入快照，原文件保留，包括 `slot0.state` / `slot0.properties`。损坏的旧包也保留供检查，不会作为空档自动覆盖。迁移标记 `progress-v1.migrated` 防止删除新槽位后被旧档重新填回；`selected-slot` 记录上次成功开局的编号。旧文件仅作迁移备份，不再参与新的自动保存。

## 手柄与画面

有线和蓝牙手柄在游戏中使用 LibretroDroid 的按键和摇杆映射（包含 Android 和 RetroPad 的 A/B、X/Y 对调，以及 `controllerNumber` 分端口）。FBNG 菜单用 A 确认、B 返回。在游戏中，按 Android 识别为 MENU 或 BUTTON_MODE 的手柄键，或使用系统返回，即可打开暂停页。

应用只适配横屏，从启动起固定为横屏，不随设备转动切换成竖屏，大屏同样申请保留横屏限制。游戏库、详情、设置、暂停页和弹窗遵守同一限制。游戏画面铺满安全区内的播放区域，由 LibretroDroid 按核心报告的宽高比居中：比屏幕窄就左右留黑边，比屏幕矮就上下留黑边。比例来自核心的 AV info，运行中如果核心用 `SET_GEOMETRY` 改了比例，黑边会跟着重算。读不到比例时才退回 4:3，画面仍然不缩小。

黑边保持纯黑，无论宽窄都不放常驻按钮，也不叠加悬浮控件，操作集中在暂停页，因此不依赖加载前预测黑边尺寸，不为控件缩小游戏画面。暂停页使用不透明背景，只在暂停或出错时显示。`MainActivity` 自己处理 `configChanges`，游戏画面是同一个 `GLRetroView`，只改它的尺寸，不新建核心。横屏中的折叠、窗口大小、系统栏和挖孔变化都会触发布局重算，设备转动不会切换为竖屏。系统如果仍然重建 Activity（比如没列进 `configChanges` 的变化），这次游戏会结束，进度靠自动存档恢复。`GLSurfaceView` 不能跨进程保留，进程死亡后会在下次启动游戏时自动读档。

游戏库在窗口宽度达到 600dp，或处于书本姿态的竖直铰链时，用左侧导航栏，更窄的窗口用底部导航栏。壳层外边距统一 16dp，左侧栏缩为 96dp，为分页目录留出更多空间。
