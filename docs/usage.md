# 使用说明

## 配置游戏库目录

在「设置 → 导入」里选「添加文件夹」，可以添加多个本地目录。添加后和每次启动应用时，应用会递归扫描这些目录里的 ZIP。目录有变动时也可以选「重新扫描」。扫描结果会显示已识别的游戏和 BIOS 数量。选择目录旁的「移除」并确认后，原文件和存档会保留。

扫描时读取 ZIP 的文件索引来识别套件。再次扫描时，应用会复用大小和修改时间都未变的文件结果。后台扫描期间保留当前列表、页码和焦点，新结果在扫描完成后更新。开始游戏时，应用会完整校验该游戏和它所需的父套件及 BIOS。

新增游戏时请把 ZIP 放到所配置的目录。多个版本共用相同 ROM 内容时，请用对应的 FBNeo 套件名命名 ZIP。旧版已导入的 ZIP 仍可使用，也可按已记录的原始文件名搜索。

游戏库会显示已识别的游戏。克隆版缺少父套件或 BIOS 时，详情会列出缺少的 ZIP。游戏、父套件和 BIOS 可以来自不同目录，也可以与旧版已导入的 ZIP 搭配。如果游戏 ZIP 已经包含所需的父套件和 BIOS 文件，就可以直接启动。目录里的 ZIP 只在启动相关游戏时复制到临时目录。

## 游戏封面

收藏、最近的预览和游戏详情支持真实封面。联网时，应用在后台为收藏或成功玩过的游戏获取缺失封面，不扫描下载整个游戏库。断网时任务等待联网，关闭界面后也由系统安排继续，系统省电限制可能延后执行。已有封面保存在应用私有目录，离线可用，下载失败时保留旧图，没有图片时保留游戏名和封面占位。

「设置 → 游戏封面」提供「获取缺失封面」和「更新封面」，两者仍只处理收藏或玩过的游戏，后者会重新下载已有图片。手动任务显示等待、更新张数或失败状态。游玩范围复用「最近」中的成功启动记录，已有记录在升级后也可获取封面。取消收藏后，已玩过的游戏仍会参与获取，已有图片会保留。选择「清除下载封面」并确认后，应用移除已下载的封面并暂停自动下载。选择「获取缺失封面」或「更新封面」可恢复自动下载。

图源使用 `Named_Boxarts` 目录的真实封面。内置索引按固定 DAT 的英文描述匹配，缺图时沿 `cloneof` 查找父游戏的封面。手动更新会从同一路径获取最新图片。APK 只包含路径索引。本地自定义封面目前还未实现。[Libretro FBNeo 图库](https://github.com/libretro-thumbnails/FBNeo_-_Arcade_Games)

图库新增或重命名图片后，可在仓库根目录运行 `python3 tools/update_cover_index.py` 更新内置索引，也可用 `--tree` 指定已保存的完整 GitHub tree 响应。[封面索引脚本](../tools/update_cover_index.py)

## 浏览与筛选

启动后进入「收藏」。从「收藏」「最近」或「游戏库」选择游戏，会先打开游戏页，可开始游戏、读档、添加到收藏或取消收藏。「最近」按实际启动游戏的顺序排列，同一款游戏只显示一次，重开应用后仍会保留。

用手柄 L1 / R1 在「收藏」「最近」「游戏库」和「设置」之间切换。收藏每页横排四张卡片，左右选卡，到达边缘后继续按即可翻页。最近每页左侧显示五条记录，上下选择游戏并更新右侧封面，左右翻页。游戏库每页按行排列两列四行，显示游戏名、ROM 文件名及启动依赖状态。上下选行，左右换列，越过最外列时翻页并尽量保留当前行。游戏库可按状态筛选，也可按手柄 Y 打开字母筛选。

字母筛选支持字母、数字、点、下划线和连字符，也可退格或清空。选择「完成」后应用筛选并回到第一页，返回或关闭面板会放弃本次修改，恢复原来的筛选、页码和游戏焦点。无结果时仍可重新打开面板编辑。如果搜索命中的游戏都缺少依赖，可以按 A 切回「全部状态」并保留搜索词。筛选匹配中文名拼音首字母、英文描述、套件文件名和实际来源 ZIP 文件名，忽略大小写，例如 SGZJ 匹配三国战纪，HJDT 匹配合金弹头，KOF98 或 kof98.zip 匹配拳皇对应文件。

进入设置后，用方向键上下切换左栏分类，按右键进入该分类的内容，按 B 回到左栏。关闭系统目录选择器后，焦点回到「添加文件夹」。同步页说明存档当前只保存在本机。

在「设置 → 关于」查看当前应用版本和核心版本。进入「应用更新」面板后按 A 可检查更新，发现新版后可在同一面板下载并按系统提示安装。Debug 和 Release 包都会在启动时检查更新，也都支持手动更新。

## 暂停与重新开始

游戏中使用系统返回或手柄暂停键会打开游戏页，并暂停画面和声音。返回或再按暂停键恢复游戏；确认框打开时，返回只取消最上层。主手柄断连同样会暂停，重新连接后自行恢复。

每款游戏固定有 3 个槽位。开局默认选中上次成功启动的槽位，可在开始游戏前切换。暂停时只可操作本局槽位。「保存并退出」和切到后台会更新本局槽位。保存失败会留在暂停页提示重试。

需要从头开始时，在开局前选中槽位并「删除进度」，确认后该槽位变空，再开始即可。暂停时删除本局槽位，会明确确认「删除并结束本局」：结束游戏、阻止后续自动保存，回到同款游戏的开局页，选中刚清空的槽位。固定编号仍保留，历史快照不受影响。

## 存档与读档

槽位负责持续游玩的进度，快照负责保留某个时刻的历史进度。开局前默认选中上次成功使用的槽位，首次为槽位 1；选择槽位不立即启动，按「开始游戏」才恢复其进度。空槽位从头开始。恢复失败会保留文件并禁止自动覆盖，可退出后应用兼容快照，或明确删除该槽位后重新开始。

暂停时从「快照」标签选择「生成快照」，保存当前运行进度。生成快照不改变自动保存目标，也不隐式更新槽位。开局和暂停页用手柄 L1 / R1 切换「进度」和「快照」。快照按生成时间倒序排列，焦点在快照行时用方向键左右翻页，也可用上一页或下一页按钮。旧版迁入的快照标记为「旧版存档」。快照读取失败时可在该标签内重试，仍可开始游戏或恢复本局。

开局前应用快照时，先选快照，再选目标槽位，最后确认覆盖。成功后选中目标槽位，仍需按「开始游戏」。暂停时应用快照的目标固定为本局槽位，确认后同时覆盖该槽位文件和当前实际运行进度，游戏保持暂停；之后的自动保存使用应用后的进度。原快照保留，不会被消耗或跟随游玩更新。核心版本不一致时会在确认框说明，FBNeo 不保证跨版本读档。

应用过程中暂停自动保存并禁止恢复、退出、重复应用与删除。读取或写入失败保留原槽位；已开始替换运行状态时会尝试恢复原状态，恢复失败则停止游戏并禁用自动保存，避免写坏原进度。删除快照需确认，只删除历史副本，不影响已经恢复到槽位或正在运行的进度。

新槽位保存在 `files/states/<套件名>/progress/`，快照保存在同级的 `snapshots/` 目录。从旧版本首次升级时，旧自动档迁入槽位 1，旧自动档和所有手动档都迁入快照，原文件保留作备份，不再参与新的自动保存。损坏的旧包也保留供检查，不会作为空档自动覆盖。存储位置与文件格式见[架构与数据](architecture.md#本地数据)。

## 手柄与画面

有线和蓝牙手柄在游戏中使用 LibretroDroid 的按键和摇杆映射（包含 Android 和 RetroPad 的 A/B、X/Y 对调，以及 `controllerNumber` 分端口）。FBNG 菜单用 A 确认、B 返回。在游戏中，按 Android 识别为 MENU 或 BUTTON_MODE 的手柄键，或使用系统返回，即可打开暂停页。

应用仅适配 RP6 掌机，从启动起固定横屏。游戏库、详情、设置、暂停页和弹窗遵守同一限制。游戏画面铺满安全区内的播放区域，由 LibretroDroid 按核心报告的宽高比居中。比屏幕窄就左右留黑边，比屏幕矮就上下留黑边。比例来自核心的 AV info，运行中如果核心用 `SET_GEOMETRY` 改了比例，黑边会跟着重算。读不到比例时才退回 4:3，画面仍然不缩小。

横屏窗口和系统安全区变化时，应用调整游戏画面尺寸并继续当前会话。系统重建 Activity 或结束应用进程时，本局会结束，下次启动游戏时从自动保存的进度恢复。
